1. Full Technology Stack & Tools Used

BACKEND FRAMEWORK
Django 5.2 & Python 3.11/3.13

Follows the Model-View-Template (MVT) architecture. Django handles security, user session management, routing, database ORM, and URL mapping across modular apps.

FRONTEND DESIGN SYSTEM
Bootstrap 5 + Dark Glassmorphism UI

Custom CSS design tokens (in static/css/custom.css) providing vibrant gradients, semi-transparent frosted glass panels, responsive grids, and FontAwesome 6 icons.

DATA ENGINEERING & CLEANING
Pandas, NumPy, Scikit-Learn

Used for fast matrix manipulation, outlier calculation (IQR/Z-Score bounds), median/mode missing value imputation, and categorical Label Encoding.

MACHINE LEARNING (AutoML)
Scikit-Learn Algorithms

Trains Random Forest, Support Vector Machines (SVM), Decision Trees, Logistic Regression, and K-Nearest Neighbors (KNN). Ranks models by R² score, Accuracy, F1-Score, and Confusion Matrix.

WEB SCRAPING ENGINE
Requests + BeautifulSoup4

Fetches HTML content from any public URL, parses <table> elements, cleans extracted cells into Pandas DataFrames, and converts them to datasets.

PDF REPORT ENGINE
ReportLab 5.0

Generates executive summary PDF reports dynamically containing dataset metrics, data health scores, cleaning recommendations, and structured formatting.

3. Expected Jury Viva Questions & Exact Answers

Q1: Which architecture pattern did you follow for building this web application?
Answer: We used Django's MVT (Model-View-Template) architecture. The Model layer handles data models and database operations via Django ORM. The View layer contains business logic and Python processing. The Template layer uses HTML5, Bootstrap 5, and Jinja-like Django template language for rendering UI components.
Q2: How does the Automated AI Cleaning functionality work under the hood?
Answer: Our cleaning engine is implemented in apps/cleaner/services.py. It performs four main operations:
1. Duplicate Removal: Calls df.drop_duplicates().
2. Missing Value Imputation: Fills numerical missing values using column median/mean (df[col].fillna()) and categorical missing values using mode.
3. Outlier Handling: Calculates Interquartile Range (IQR = Q3 - Q1) and caps extreme values outside [Q1 - 1.5*IQR, Q3 + 1.5*IQR].
4. Categorical Encoding: Uses Scikit-Learn's LabelEncoder to convert text categories into numerical values for ML training.
Q3: How do you maintain dataset history when a user cleans or modifies a file?
Answer: We implemented Immutable Dataset Versioning using two Django models in apps/datasets/models.py: Dataset and DatasetVersion. When a raw dataset is uploaded, it gets saved as version_number = 1. When automated cleaning or filtering is performed, a new DatasetVersion object (v2, v3) is created and linked to the main dataset. The original raw file is never overwritten.
Q4: What machine learning algorithms are supported in your AutoML Studio, and how are they evaluated?
Answer: Our AutoML Studio (apps/ml_studio/services.py) supports both Regression and Classification:
• Classification: Random Forest Classifier, Decision Tree, Logistic Regression, K-Nearest Neighbors (KNN), and Support Vector Classification (SVC). Evaluated using Accuracy, Precision, Recall, and F1-Score.
• Regression: Random Forest Regressor, Linear Regression, Decision Tree Regressor. Evaluated using R² Score (Coefficient of Determination) and Mean Squared Error (MSE).
Q5: How does the Web Scraper extract tables from external websites?
Answer: The Web Scraper (apps/scraper/services.py) takes a URL, sends an HTTP request using Python's requests library, and parses the HTML DOM tree using BeautifulSoup4. It finds all <table> tags, extracts header row <th> and content rows <td>, constructs a Pandas DataFrame, and allows the user to save it directly into Dataset Manager with 1-click.
Q6: How did you deploy the application live, and how do you manage database state on Vercel?
Answer: We deployed IntelliHub AI on Vercel's Serverless Platform using WSGI adapter configuration (intellihub/wsgi.py). Because serverless environments use read-only file systems, we configure SQLite database to run from the /tmp directory, and use signed cookie session backend (django.contrib.sessions.backends.signed_cookies) so user authentication state is securely maintained in browser cookies across serverless executions.
Q7: What security features are built into your platform?
Answer:
1. Password Hashing: Uses Django's default PBKDF2 algorithm with SHA-256 hash.
2. CSRF Protection: All POST forms include {% csrf_token %} to prevent Cross-Site Request Forgery.
3. Role-Based Access Control (RBAC): Custom user roles (ADMIN, DATA_SCIENTIST, RESEARCHER, STUDENT, COMPANY) control permissions across admin panel and studio tools.
4. Session Security: Configured SESSION_COOKIE_HTTPONLY = True and SESSION_COOKIE_SAMESITE = 'Lax' to protect against XSS and session hijacking.
Q8: What happens if a first-time user registers and logs into the platform?
Answer: We designed a First-Time User Onboarding Flow in apps/dashboard/views.py. When a user has 0 uploaded datasets (user_datasets == 0), a prominent welcome card automatically prompts them to upload their first dataset or scrape data from the web before proceeding to EDA or AutoML.
