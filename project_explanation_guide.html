Chapter 1: What is IntelliHub AI? (Simple Beginner Story)

Imagine you work in a company and your boss gives you a messy Excel sheet with 50,000 rows. It has missing customer ages, duplicate orders, weird negative numbers, and text categories. Normally, a data scientist has to open Python in Jupyter Notebooks, write 300 lines of Pandas code to clean it, open PowerBI to make graphs, and open custom tools to train Machine Learning models.

IntelliHub AI changes this completely! It is a web application where anyone — even a non-technical beginner — can upload a CSV/Excel file, click 1 button to automatically clean errors, view interactive charts, scrape tables directly from web URLs, auto-train AI models, and download a finished executive PDF report without writing a single line of code!

Chapter 2: Full Technology Stack Used

Here are the 6 technology pillars used to build IntelliHub AI and why each was chosen:

1. Python (3.11 / 3.13)

The primary backend language. Python is the world standard for Data Science and Artificial Intelligence because of its rich scientific libraries like Pandas, NumPy, and Scikit-Learn.

2. Django 5.2 Framework

A high-level Python web framework. It handles user authentication, session security, database ORM queries, CSRF security tokens, and URL routing out of the box using clean Python code.

3. Bootstrap 5 + Dark Glassmorphic UI

Used for the user interface (UI). Provides responsive layouts across desktop, laptop, and mobile screens, styled with semi-transparent frosted glass cards, cyan highlights, and FontAwesome 6 icons.

4. Pandas & NumPy Engine

Pandas loads CSV and Excel files into memory as 2D tables called DataFrames. NumPy performs fast numerical computations and array operations.

5. Scikit-Learn (ML Library)

The core Machine Learning library. Performs data encoding (LabelEncoder), train/test dataset splitting, and model fitting for Random Forest, SVM, Decision Trees, KNN, and Logistic Regression.

6. ReportLab 5.0 & BeautifulSoup4

ReportLab: Dynamically compiles data metrics and charts into downloadable executive PDF reports. BeautifulSoup4: Parses HTML web pages to extract table data for the Web Scraper.

Chapter 3: How Django Works (MVT Architecture Explained)

If the jury asks "What architectural pattern does your application follow?", answer: "Django's MVT Architecture (Model - View - Template)".

M - Model

Defines database tables as Python classes in models.py. Django ORM automatically maps Python attributes to SQL database columns without manual SQL scripting.

V - View

The business logic layer in views.py. It accepts incoming HTTP requests from the web browser, processes data using Python algorithms, and passes context data to the Template.

T - Template

The user interface HTML page in templates/*.html. It renders dynamic content using Django template tags like {{ user.username }} and {% for item in list %}.

Chapter 5: Detailed Page-by-Page & Code Walkthrough

1Authentication & User Management (Accounts App)

URL Routes: /accounts/login/, /accounts/register/, /accounts/profile/

  • Registration Page: User inputs Username, Email, Password, and selects a Role. Handled by UserRegistrationForm in apps/accounts/forms.py.
  • Login Page: Handled by login_view in apps/accounts/views.py. Calls Django's authenticate() and login(). If credentials fail, displays message: "Invalid username/email or password. Please check your credentials."
  • Session Management: Configured in intellihub/settings.py with SESSION_ENGINE = 'django.contrib.sessions.backends.signed_cookies' which encrypts and stores session data inside browser cookies for Vercel serverless compatibility.
  • Profile & Settings Page: Allows user to edit Bio, Education, Company, GitHub, LinkedIn links, and upload photo. Integrated directly into the sidebar navigation.

2Dashboard Overview (Dashboard App)

URL Route: /dashboard/ | Template: templates/dashboard/dashboard.html

  • First-Time User Prompt: Controlled by is_first_time = (user_datasets == 0) in apps/dashboard/views.py. When a user has 0 datasets, a glowing welcome card prompts them to upload their first dataset or scrape data.
  • KPI Metric Cards: Displays total datasets, active ML models trained, total predictions run, and average accuracy score.
  • Sidebar Navigation: Displays links for Dashboard, Dataset Manager, AI Data Cleaner, Exploratory EDA, ML Studio, AI Analyst Assistant, Universal Web Scraper, AI Report Generator, and Profile & Settings.

3Dataset Manager & Versioning (Datasets App)

URL Route: /datasets/ | Template: templates/datasets/dataset_list.html

  • File Upload: Users upload CSV, Excel (.xlsx), or JSON files. Handled by dataset_upload view in apps/datasets/views.py.
  • Version Control Engine: Defined in apps/datasets/models.py:
    • Dataset model: Stores metadata (name, description, owner, timestamps).
    • DatasetVersion model: Stores actual file reference, version_number (1, 2, 3), row count, column count, memory usage, missing value count, duplicate count.
  • Immutable History: When data is cleaned, version v2 is created. Original raw data v1 is preserved and never overwritten!

4Automated AI Data Cleaner (Cleaner App)

URL Route: /cleaner/ | Template: templates/cleaner/cleaner_home.html

  • Health Status Score: Scans dataset for missing values and duplicates to display "Needs Attention" or "Optimal Clean".
  • 1-Click Execute Auto Clean: Runs perform_auto_clean() in apps/cleaner/services.py:
    1. Removes duplicate rows: df.drop_duplicates().
    2. Imputes missing numerical values with column median/mean.
    3. Caps numerical outliers outside 1.5*IQR bounds.
    4. Converts text categories into numbers using Scikit-Learn LabelEncoder.
  • Download Cleaned Dataset Button: A green button appears after auto-clean execution allowing users to download the cleaned CSV file version directly to their computer.

5Universal Web Scraper (Scraper App)

URL Route: /scraper/ | Template: templates/scraper/scraper.html

  • URL Ingestion: Accepts any website URL containing HTML tables.
  • Scraping Algorithm: Implemented in apps/scraper/services.py:
    1. Sends HTTP GET request: requests.get(url).
    2. Parses HTML DOM tree using BeautifulSoup4 to locate <table> elements.
    3. Extracts headers (<th>) and rows (<td>) into a Pandas DataFrame.
  • Portrait Mode Display: Styled with CSS word-break: break-word; white-space: normal; so scraped table data wraps vertically on mobile and narrow displays without breaking layout. Displays up to 25 preview rows!
  • 1-Click Save as Dataset: Saves scraped web tables directly into Dataset Manager for cleaning and model training.

6AutoML & ML Studio (ML Studio App)

URL Route: /ml-studio/ | Template: templates/ml_studio/ml_home.html

  • Target Variable Selection: User selects which column to predict (e.g. "House Price" or "Customer Churn").
  • Auto Problem Type Detection: If target column is numeric with many unique values → Regression. If text/categorical or few unique integers → Classification.
  • Model Training & Benchmarking: In apps/ml_studio/services.py, automatically splits data into 80% train / 20% test and trains multiple algorithms:
    • Random Forest Classifier / Regressor
    • Support Vector Machines (SVC / SVR)
    • Decision Trees
    • Logistic Regression / Linear Regression
    • K-Nearest Neighbors (KNN)
  • Leaderboard: Displays models ranked by Accuracy / R² score along with Precision, Recall, F1-Score, and Confusion Matrix.

Chapter 7: Deep Data Science Algorithms & Math Logic

If the jury asks "What mathematical formulas or data processing logic did you use?", explain these exact 4 algorithms:

1. Outlier Detection using Interquartile Range (IQR)
Math Formula:
Q1 = 25th Percentile of column data
Q3 = 75th Percentile of column data
IQR = Q3 - Q1
Lower Bound = Q1 - (1.5 * IQR)
Upper Bound = Q3 + (1.5 * IQR)

Logic: Any row value below Lower Bound or above Upper Bound is an extreme outlier. In apps/cleaner/services.py, we cap those values to the upper and lower boundary numbers so extreme data doesn't skew machine learning models!
2. Missing Value Imputation
Logic:
• For Numerical Columns: Replaces missing NaN cells with column Median (or Mean) via df[col].fillna(df[col].median()).
• For Categorical Columns: Replaces missing text cells with column Mode (most frequent value).
3. Categorical Label Encoding
Logic: Machine Learning algorithms cannot calculate math on string text like "High", "Medium", "Low". We use Scikit-Learn's LabelEncoder() to convert text strings into numerical integers: High = 0, Medium = 1, Low = 2.
4. Model Evaluation Metrics ($R^2$ Score & Accuracy)
Classification Accuracy: Ratio of correct predictions over total predictions.

Regression $R^2$ Score (Coefficient of Determination): Measures how well predictions match actual values relative to the mean value:
R² = 1 - (Sum of Squared Residuals / Total Sum of Squares)
$R^2 = 1.0$ represents a 100% perfect prediction model.

Chapter 8: How Vercel Cloud Serverless Deployment Works

How the site runs live at https://intellihub-ai-portal.vercel.app/:

  1. Serverless Execution: Hosted on Vercel using Python 3.12 serverless functions via intellihub/wsgi.py.
  2. Database in /tmp: Because Vercel's main container environment is read-only, our SQLite database file db.sqlite3 is loaded from /tmp for lightning-fast queries.
  3. Signed Cookie Sessions: Configured SESSION_ENGINE = 'django.contrib.sessions.backends.signed_cookies' in intellihub/settings.py. Encrypted session tokens store login state inside browser cookies so users stay logged in across serverless container restarts.
  4. Static File Serving: Handled by WhiteNoise 6.12 middleware to serve CSS, JavaScript, and fonts directly with memory caching and gzip compression.

Chapter 10: 30 Master Jury Viva Questions & Exact Answers

Q1: What is the main objective of IntelliHub AI?
Answer: To provide an all-in-one, zero-code enterprise web portal that combines web scraping, data ingestion, automated cleaning, exploratory analysis, AutoML model training, and executive PDF reporting under a single unified platform.
Q2: Which backend framework and language did you use?
Answer: Python (3.11 / 3.13) and the Django 5.2 web framework.
Q3: How do you handle missing values in a dataset?
Answer: In apps/cleaner/services.py, numerical missing values are imputed using column median/mean, and categorical missing values are imputed using statistical mode.
Q4: How does your dataset versioning feature work?
Answer: Using two Django models: Dataset and DatasetVersion. Every time a dataset is modified or cleaned, a new DatasetVersion record (v1, v2) is created. The original raw file is never overwritten.
Q5: How does the web scraper extract data?
Answer: It sends an HTTP request using Python's requests library, parses HTML DOM table nodes (<table>) using BeautifulSoup4, converts extracted rows into a Pandas DataFrame, and saves it into Dataset Manager with 1-click.
Q6: What ML models are included in AutoML Studio?
Answer: Random Forest, Support Vector Machines (SVM), Decision Trees, Logistic Regression, Linear Regression, and K-Nearest Neighbors (KNN) from Scikit-Learn.
Q7: How are ML models evaluated?
Answer: Classification models are evaluated using Accuracy, Precision, Recall, F1-Score, and Confusion Matrix. Regression models are evaluated using R² Score and Mean Squared Error (MSE).
Q8: How do you handle categorical text columns before model training?
Answer: We convert text categories into numerical integers using Scikit-Learn's LabelEncoder.
Q9: What library is used to generate PDF reports?
Answer: ReportLab 5.0 in Python.
Q10: Where is your application hosted live?
Answer: Hosted live on Vercel Serverless platform at https://intellihub-ai-portal.vercel.app/.
Q11: How do you secure user authentication and passwords?
Answer: Passwords are hashed using PBKDF2 with SHA-256. All POST forms use CSRF protection tokens, and session cookies use HTTPOnly and SameSite=Lax flags.
Q12: How is the UI designed?
Answer: Responsive Bootstrap 5 layout with a custom Dark Glassmorphism aesthetic featuring semi-transparent frosted glass panels and glowing cyan highlights.
Q13: How does the onboarding flow work for first-time users?
Answer: When a user has 0 datasets (user_datasets == 0), a glowing welcome card automatically appears on the dashboard prompting them to upload a dataset or scrape data before accessing analytics.
Q14: How do you remove duplicate rows?
Answer: Using Pandas df.drop_duplicates() method inside apps/cleaner/services.py.
Q15: How do you detect numerical outliers?
Answer: Using the Interquartile Range (IQR) method: [Q1 - 1.5*IQR, Q3 + 1.5*IQR].
Q16: What is the purpose of the AI Analyst Assistant?
Answer: It allows users to ask questions about active datasets in plain English without writing manual database queries.
Q17: How is user role management structured?
Answer: Custom Django User model extending AbstractUser with roles: ADMIN, DATA_SCIENTIST, RESEARCHER, STUDENT, COMPANY.
Q18: What is the difference between Regression and Classification in AutoML?
Answer: Regression predicts continuous numerical quantities (e.g. house price). Classification predicts discrete categories (e.g. Yes/No, Spam/Ham).
Q19: How are static assets (CSS, JS) served on Vercel?
Answer: Served using WhiteNoise 6.12 middleware with memory caching and gzip compression.
Q20: Can users download cleaned data?
Answer: Yes, a green "Download Cleaned Dataset" button appears in the AI Data Cleaner as soon as auto-cleaning is executed.
Q21: How do you prevent table layout breakage in the Web Scraper?
Answer: Configured cell text wrapping using CSS word-break: break-word; white-space: normal; so scraped table cells wrap vertically on mobile and portrait views.
Q22: Why choose Django over Flask?
Answer: Django is an enterprise "batteries-included" framework with built-in ORM, admin portal, user authentication, and CSRF security middleware out of the box.
Q23: What database engine is used?
Answer: SQLite database optimized for serverless deployment with sessions managed via signed cookie backend.
Q24: What future scope is planned for IntelliHub AI?
Answer: Direct integration with OpenAI/Claude LLM APIs, 1-click SQL database connectors (PostgreSQL/Snowflake), and Apache Kafka real-time data streaming.
Q25: Who built this project?
Answer: Suraj Vaghela, Nandish Patel, and Himanshu Namsa from LJ University.
Q26: What happens during model train/test split?
Answer: We split data into 80% Training set (to fit model weights) and 20% Testing set (to evaluate unseen accuracy) using train_test_split().
Q27: How does your app prevent SQL Injection?
Answer: Django ORM uses parameterized SQL queries under the hood, completely escaping untrusted user inputs.
Q28: How do you track memory usage of uploaded datasets?
Answer: In apps/datasets/views.py, we calculate DataFrame memory using df.memory_usage(deep=True).sum() and convert bytes to KB/MB string.
Q29: How is the landing page organized?
Answer: Features hero banner, interactive live demo tabs, module feature cards, tech stack highlights, pricing tier preview, and direct sign-up CTAs.
Q30: What is the main innovation of your platform?
Answer: Integrating the entire end-to-end data lifecycle — ingestion, scraping, cleaning, versioning, EDA, AutoML, and executive PDF reporting — into one seamless zero-code SaaS web portal.
